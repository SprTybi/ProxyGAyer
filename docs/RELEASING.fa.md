# ساخت و انتشار ریلیز

همهٔ دستورها از ریشهٔ همین مخزن اجرا می‌شوند؛ وابستگی به پوشهٔ `source` یا فایل‌های بیرون مخزن وجود ندارد.

## انتشار خودکار در GitHub

1. تغییرات این مخزن را Commit و روی `master`، Push کن.
2. در GitHub به **Actions → Release → Run workflow** برو.
3. شاخهٔ `master` و نسخهٔ `1.0.0` را وارد کن و اجرا را شروع کن.
4. بعد از موفق‌شدن workflow، فایل‌ها در بخش **Releases** منتشر می‌شوند.

نیازی به ورود GitHub CLI روی کامپیوترت نیست؛ workflow از توکن خود GitHub استفاده می‌کند. این اجرا واقعاً ریلیز را منتشر می‌کند. نسخه‌ای را انتخاب کن که هنوز منتشر نشده است.

راه جایگزین، Push تگ همان نسخه است:

```powershell
git tag v1.0.0
git push origin v1.0.0
```

یکی از دو روش را برای هر نسخه استفاده کن. برای نسخهٔ بعدی مثلاً `1.0.1` را بده و متن توضیحات را در `docs/releases/v1.0.1.md` قرار بده.

## ساخت فایل‌ها روی کامپیوتر خودت

با .NET 10 SDK و Git نصب‌شده:

```powershell
.\build-release.ps1 -Version 1.0.0
```

خروجی‌ها داخل `artifacts/releases/v1.0.0` همین مخزن قرار می‌گیرند. این اسکریپت فقط فایل‌ها را می‌سازد؛ منتشر نمی‌کند. در صورت نبود بسته‌های runtime در کش، آن‌ها از NuGet رسمی دریافت می‌شوند.

| فایل پیوست | کاربرد |
| --- | --- |
| `ProxyGAyer-v1.0.0-standalone-win-x64.exe` | یک فایل مستقل؛ بدون نصب .NET یا DLL کنار آن |
| `ProxyGAyer-v1.0.0-win-x64.exe` | نسخهٔ سبک؛ نیازمند .NET 10 Desktop Runtime |
| `ProxyGAyer-v1.0.0-win-x64.zip` | نسخهٔ سبک همراه راهنمای کوتاه و مجوز |
| `SHA256SUMS.txt` | هش فایل‌ها برای بررسی دانلود |

نسخهٔ Standalone بزرگ‌تر است، چون .NET داخل آن قرار دارد. کاربران این نسخه فقط همان EXE را دانلود و اجرا می‌کنند. فایل‌های خودکار **Source code** در GitHub جای فایل اجرایی را نمی‌گیرند.

برای انتشار دستی، [فرم ساخت ریلیز](https://github.com/SprTybi/ProxyGAyer/releases/new) را باز کن، تگ و عنوان را مشخص کن، [متن توضیحات](releases/v1.0.0.md) و فایل‌های بالا را پیوست کن و Publish را بزن. خروجی‌های محلی و کش ساخت در Git نادیده گرفته می‌شوند و نباید به فایل‌های سورس اضافه شوند.
